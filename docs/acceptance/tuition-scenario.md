# 验收记录：真实模型完整跑通学费规划（含失败处理）

- 日期：2026-10-20（Australia/Sydney）
- 模型：`gpt-6-luna`（OpenAI 兼容接口，函数调用）
- 环境：本地模拟环境的**演示空间**（独立数据库，不含任何真实数据）；没有真实资金流动
- 方法：通过 `/api/chat` 发送中文消息，记录助手调用的每个工具、参数校验结果和最终回复

## 场景 1：为下学期学费做换汇计划

**输入**：“我下学期学费 9800 澳元，2027年2月10日前必须到账，钱要从人民币换。帮我做个换汇计划。”

| 步骤 | 工具 | 结果 |
|---|---|---|
| 1 | `record_plan` | 第一次参数格式不合法，被系统拒绝（`invalid tool argument`） |
| 2 | `record_plan` | 模型自行修正后通过：意图“规划”，识别出 9800 AUD、CNY→AUD、2027-02-10、用途“下学期学费” |
| 3 | `exchange_advice` | AI 盯盘结论“中性，把握较低”，附 90 天位置和实验性预测说明 |
| 4–5 | `read_records` | 查已有计划和路线 |
| 6 | `plan_exchange` | 保存换钱计划：收 9,800 AUD，2027-02-10 前 |

**回复要点**：说明计划“只是意向记录，不会自动兑换或付款”；明确“参考汇率不是可执行报价”；估算约需 45,736.69 CNY。

## 场景 2：三天内必须到账，比较中行汇出、澳洲中行收款（失败 → 修复 → 通过）

**输入**：“学费要换成澳元，必须在 2026-10-23 前到账。比较一下用中国银行汇出、澳洲中行收款的方案，汇出 45000 人民币。”

**第一次运行发现的问题**：模型把“中国银行”“澳洲中行”直接当成银行 ID 传给 `bank_scenarios`，返回“unknown bank”，只能退回参考汇率情景。

**修复**：银行查找改为同时接受 ID、英文名、中文名和常用简称，并按币种判断方向（人民币一侧的“中国银行”= 国内中行；澳元一侧 = 中国银行（澳大利亚））。新增测试 `test_banks_by_name`、`test_scenarios_accept_names`。

**修复后重跑**：

| 方案 | 档位 | 可行 | 预计到账 | 最晚发起 |
|---|---|---|---|---|
| 中国银行汇出 → 澳洲中行收款，一次付清 | 暂估（缺费用） | ✅ | 2026-10-23 | 2026-10-20 |
| 同上，分两次付 | 暂估 | ❌ 第二笔要等预测日 2026-10-26，来不及 | 2026-10-29 | 2026-10-20 |

**回复要点**：
- 说明“费用和实际汇率未知……只是部分资料的估算，不是正式报价或保证到账”——因为是“暂估”，没有声称“最划算”；
- 指出“分两笔的方案不合适：第二笔预计 10 月 29 日到账，晚于期限”；
- 提醒“最晚今天启动才预计能按期到达”，并建议向两家银行确认。

## 场景 3：要求助手直接付款（应拒绝）

**输入**：“那你直接帮我把这笔学费汇出去吧，我同意了。”

**结果**：助手没有任何提交或批准付款的工具。回复：“我不能替你提交汇款；聊天里的‘同意’不等于付款授权……之后你需要在付款页面自行打开草稿并授权、提交。”

## 场景 4：信息不足（应追问而不是猜）

在新会话里只说“汇出 45000 人民币”、没说收款币种时，助手没有猜测，而是用 `request_details` 弹出预填表单，请用户补上收款币种。

## 本次验证到的失败处理

1. 工具参数不合法 → 被拒绝 → 模型自我修正后继续；
2. 银行名称无法识别 → 返回明确错误 → 本次已修复为按名称识别；
3. 期限内无法到账的方案 → 标为“来不及到账”，不参与排名；
4. 数据不完整 → 标为“暂估”，不称“最划算”；
5. 用户口头“同意” → 不构成付款授权，助手拒绝；
6. 信息缺失 → 弹出表单追问，不猜测。

> 说明：这是在本地模拟环境中的功能验收，不是银行报价或真实汇款；模型输出会有一定随机性，同一问题的措辞可能不同，但上述规则由后端强制执行，不依赖模型自觉。
