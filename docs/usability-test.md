# 可用性测试材料（3–5 位未参与开发的同学）

目的：验证“没用过的人能不能独立完成核心任务”，以及他们**是否看得懂估算和真实报价的区别**。这是小规模可用性验证，不是市场调研。

## 准备

- 设备：一台电脑（Chrome）+ 一部手机；打开 http://localhost:8787
- 每位参与者用**自己注册的新账户**（数据互相隔离），或点“先看看演示”
- 主持人只读任务卡，不演示、不提示；参与者边做边说出想法（出声思考）
- 每人约 20 分钟；征得同意后录屏或记笔记，不记录真实姓名和账号

## 任务卡（按顺序念给参与者）

| # | 任务 | 成功标准 |
|---|---|---|
| T1 | 注册一个账户并进入应用 | 不需要帮助完成注册 |
| T2 | 告诉 DOT 你现在有 3000 澳元和 2000 人民币 | 两个余额出现在总览 |
| T3 | 下学期学费 9800 澳元，2 月 10 日前要到账，钱从人民币换——把它记成计划 | 总览出现这笔换钱计划 |
| T4 | 看总览最上面那句话：你现在最该做什么？ | 能用自己的话说出缺口和下一步 |
| T5 | 去汇款页，金额填 45000 人民币，看换汇方案。哪个方案“最划算”？ | 能说出“暂估/情景参考不是报价”；若没有“最划算”标签，能解释原因 |
| T6 | 把截止日改成 3 天后，哪些方案来不及？ | 能指出“来不及到账”的方案 |
| T7 | 导入两份账单：借记卡（含一笔还信用卡 100）和信用卡（含消费 100、还款 100）。这个月花了多少？ | 回答“100”，不是“200” |
| T8 | 找到一笔重复的记账并删掉 | 找到疑似重复并处理 |
| T9 | 用对话让 DOT 加一个每月 13.99 澳元的订阅，然后确认 | 订阅出现在“固定支出” |
| T10 | 导出你的全部数据 | 下载到 dot-export.json |

> T7 用的示例账单在 `tests/test_money.py` 里（`DEBIT`、`CARD`），可以另存为 CSV 发给参与者。

## 结束后的 5 个问题（1–5 分）

1. 我能很快找到想做的事。
2. 我分得清“参考/估算”和“真实报价”。
3. 我相信它不会在我没确认的情况下动我的钱。
4. 动效让我更清楚发生了什么，而不是分心。
5. 我愿意继续用它管理留学的钱。

再问一句开放问题：“最让你困惑的一个地方是什么？”

## 汇总方式

- 每个任务的完成率（独立完成 / 求助后完成 / 失败）
- 所有严重程度为 3 的问题，逐条列出原话和截图
- 5 个问题的平均分
- 按“出现次数 × 严重程度”排序，前 3 个问题进入下一轮修改
